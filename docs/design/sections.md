# Page sections

Routes render feature modules as defined in [Application structure](../architecture/application.md).

Introduce sections when content or behavior needs a distinct owner. Name them for their role in the feature, keep a useful heading hierarchy, and verify reading order at narrow and wide widths. Keep private parts beside the section rather than promoting them to global components.

Choose layout from the actual user task and content. Avoid placeholder testimonials, decorative dashboards and empty sections that imply requirements nobody supplied.
