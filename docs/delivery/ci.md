# CI and task caching

[ci.yml](../../.github/workflows/ci.yml) runs checks for ready pull requests, pushes to `master` and manual dispatch. Draft pull requests skip the checks; marking a PR ready starts them, and converting it back to draft cancels an in-progress run. Format, lint, types, tests and build run as separate parallel jobs; each uses the shared CI setup action to install the pinned Node/pnpm environment and dependencies. Only the test job installs Chromium. The jobs run the same whole-workspace checks as `pnpm run ci` and require no repository secrets or remote Turbo account. The shared test configuration permits packages with no test files; a pass alone does not establish coverage. Add tests for meaningful behavior and require test files where a package needs a suite.

CI checks the whole workspace. Use `pnpm turbo run <task> --affected` locally when Git history supports it; introduce affected-only CI after its benefit and path selection are verified. Root scripts have their own responsibilities and are not selected automatically as package tasks.

Turbo caches outputs and task results according to [turbo.json](../../turbo.json). Lint, type and test tasks depend on a `transit` task so dependency changes invalidate consumers. Markdown is excluded from lint, test and build inputs, but remains an input for formatting and type checking. Site constants are included in the web package inputs, so changes invalidate its build.

Jobs use separate runners and each installs dependencies, so parallelism trades additional runner work for potentially shorter wall-clock time. No dependency or remote Turbo cache is configured; measure cache restore time and real run durations before adding one. Add remote caching through authorized account configuration rather than putting credentials in tracked files. A passing Next build does not prove Docker packaging or a production deployment. Successful `master` push runs can trigger [CD](cd.md) when explicitly enabled.
