# Explore a visual direction

Inputs are the accepted brief, realistic content, [Brand](../../../docs/design/brand.md), constraints and owned concept resources. Follow [Design workflow](../../../docs/design/workflow.md); use applicable installed craft skills without adopting a different identity.

Identify the meaningful choice in hierarchy, information order, density or interaction. Explore materially different structures when needed; a straightforward edit may use one direction. Colour swaps are not distinct concepts.

Render concepts through supported host tools at representative narrow/wide sizes, relevant themes and important states. Label static interactions and sample content. Do not claim visual verification from prose/source alone or change production code during exploration-only work.

Specify hierarchy, reading order, responsive layout, feedback and behavior using accessible primitives. Add motion/imagery only for a task purpose. Recommend a direction with rationale and tradeoffs, then hand the actual artifact to critique and its implementation details to the engineer.

Return artifacts/viewports, recommendation, content/assets, interactions, justified departures and checks. Wait for user selection only when requested or a material decision requires it. Stop at exploration when assigned; no automatic component-prototype workflow is required.
