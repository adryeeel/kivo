# Review the design

Inputs are the original task, accepted brief, [Brand](../../../docs/design/brand.md) and artifact/revision. Follow [Design workflow](../../../docs/design/workflow.md); use [critique](../critique/SKILL.md) for finding discipline and [qa](../qa/SKILL.md) for assigned runtime checks.

Follow the primary journey. Evaluate content priority, navigation, actions/feedback, credibility, responsive reading order, legibility, balance, states and brand. An old layout convention is not a reason to reject a better composition.

Use identified rendered sizes/themes for visual judgments and actual interaction for behavioral claims. Report missing evidence and perform available independent checks. Separate heuristic predictions and taste from observed failures; agent agreement cannot establish user satisfaction or conversion gains.

Inspect relevant accessibility/performance risks without claiming a complete audit or benchmark. Recommend deeper checks only when the gap matters; outside skill preferences are not universal defects.

Return prioritized screen/state or file findings with observation, user impact, confidence and smallest fix/test. Keep artifacts and production code read-only unless editing is assigned. Stop when evaluated, with remaining tradeoffs for the lead rather than an endless redesign loop.
