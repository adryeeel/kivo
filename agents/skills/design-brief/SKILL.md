# Frame the page

Inputs are the page request, content, audience/evidence and assigned brief resources. Read [Brand](../../../docs/design/brand.md), [Design workflow](../../../docs/design/workflow.md) and relevant existing UI.

State who needs to do what, where they arrive from and what they should understand/do next. Separate supplied observations from desk research, heuristics and assumptions. Use [research](../research/SKILL.md) for unresolved facts; never invent interviews, analytics or achievements.

Define information hierarchy, navigation, content and primary flow before styling. Include realistic content extremes, responsive reading order and relevant alternate/error/empty states. Do not invent asynchronous states for static content.

Identify current conventions that obstruct the task and affected shared components. Preserve brand/accessibility/boundaries while making routine layout decisions within scope. Raise missing information only when it materially changes the design; continue independent work when possible.

Return a compact task/content/flow brief, constraints, assumptions, observable acceptance checks and open questions. Name a real-user test when a consequential assumption needs one. Stop before implementation or recruitment unless assigned.
